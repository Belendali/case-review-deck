01 · Prototype in code

The demo is the spec.

For onboarding I skipped the static flow. I built the five-step experience as a working page — live preview, a cat that asks the questions, a game plan at the end — and shared a link.

PM and engineering reviewed the real interaction, not a picture of it. Decisions that used to take a week of mockups closed in a call.

02 · Skills · Game covers

Taste, written down.

Every published game needs a cover. I wrote the skill that generates it — three inputs, one contract, and a reference library the team can grow.

SceneWhat's in the game — the content list.
PreviewThe render as the visual baseline.
IntentThe mood from the creator's chat.

Contract: transform, don't invent. The game is the style guide — the skill only chooses the shot.

03 · Design the system, not the screen

When should the AI crew speak up?

Crew mode is the Pro tier. The hard part wasn't the toggle — it was deciding when to offer it, how loudly, and when to stay silent.

OFF · NEWOFFONLOCKEDON · WORKING
MODAL→CARD→INLINE→SILENT

Eight entry paths from account state × who triggers × familiarity. Offer only on real build intent; the more familiar the user, the quieter the ask. Trials count only when a playable game ships — so the crew has to be visibly better.
